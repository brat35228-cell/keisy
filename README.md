# Кейси речей — структура за ООП

Один файл `index.html` розкладено на папки. Логіка живе в класах, кнопки в розмітці викликають фасад `app`.

## Папки

| Папка | Роль |
|---|---|
| `js/models` | Предметна область: каталог, гравець, рідкість, клікер, бобри |
| `js/ui` | Екрани: вітрина, кейс, інвентар, профіль, адмін, шапка |
| `js/games` | Міні-ігри. Усі спадкують `MiniGame` і мають свій `render()` |
| `js/beaver` | Окрема валюта й ігри вкладки «Бобри» |
| `js/services` | Картинки й синхронізація з Firebase |
| `js/core` | Гроші, сховище, екранування, ідентифікатори |
| `js/app` | `GameApp` збирає все разом (композиція), `Session` тримає екран |
| `js/data` | Сирі кейси без логіки |
| `assets/items` | Наліпки речей, по теці на кейс |
| `css` | Оформлення «складу посилок» |

## Правила, яких дотримано

- **Інкапсуляція.** Стан гравця й каталогу ховається в класах, назовні йдуть методи (`credit`, `roll`, `save`).
- **Одна відповідальність.** Кейс не знає про плінко, адмінка не рахує ваги випадіння.
- **Наслідування.** `RouletteGame`, `CoinFlipGame`, `MinesGame`, `RocketGame`, `Upgrader`, `ClickerGame` розширюють `MiniGame`.
- **Поліморфізм.** Меню тримає список ігор і викликає `render()`, не розгалужуючись по типу.
- **Композиція.** `GameApp` не наслідує екрани, а складається з них.
- **Абстракція.** `RarityTable` однакова для звичайних кейсів і бобрів — різняться лише фіксовані шанси.

Збереження лишилось у тих самих ключах `cg_*`, тож старий прогрес на пристрої підхоплюється.
